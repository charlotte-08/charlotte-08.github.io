# ROAMEE 景點資料維護指南

景點資料以 `src/place-schema.js` 為唯一結構規則，分類選項以 `src/place-taxonomy.js` 為準。設計與內容維護時，不需要理解資料庫語法，只需要遵守以下原則。

「現在去哪」主題與 Surprise 標籤都有獨立登錄表。每一項包含不隨文案改變的 `id`、前台顯示的 `label`、是否啟用的 `active` 及控制順序的 `sortOrder`。新增選項時加入登錄表即可，不需要修改 schema；既有景點以 ID 關聯，因此重新命名不會讓資料失效。

## 必填內容

- 唯一 ID、景點名稱、上架狀態
- 卡片短簡介、內頁介紹
- 正確縣市、行政區、完整地址與經緯度
- 至少一張圖片及圖片來源
- 主要類別、現在去哪主題、Surprise 標籤、探索周遭分類、一日規劃主題
- 價格級距、平均消費或票價說明
- 建議停留時間
- 營業時間與預約資訊

## 不放進景點主檔

- 使用者距離、收藏狀態與搜尋紀錄
- 行程抵達時間、景點順序、交通時間與交通方式
- 共編者、附議者及使用者實際設定的停留時間

以上內容都會因使用者或單次行程改變，必須在執行時另外計算或儲存。

## 命名規則

- 景點只有一個 `name`；畫面放不下時由 CSS 顯示省略號。
- MVP 僅服務台灣，因此位置資料由 `city` 開始，不建立 `country`。
- 卡片文案使用 `summary`，景點內頁使用 `introParagraphs`。
- 圖片全部放進 `media`，第一張封面標記為 `cover`，不重複維護 `image` 與 `images`。
- 距離不得寫死在景點資料內，必須由景點座標與使用者位置計算。

## 上架前檢查

使用 `validatePlace` 或 `validatePlaces` 檢查資料。缺少 ID、名稱或圖片會視為錯誤；缺少地址、座標、停留時間或使用了分類字典以外的標籤會提出警告。
